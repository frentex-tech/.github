# Working with Frentex Tech repositories

Check the repository README and project-specific guidance before making changes.

## Propose a change

1. Describe the problem, affected users and expected behavior.
2. Keep the change focused and work on a descriptive branch.
3. Include relevant validation and screenshots for visible changes.
4. Open a pull request explaining the result, testing and any remaining limitations.
5. Request review before merging work that affects shared behavior or deployments.

Never commit passwords, tokens, recovery codes, private customer data or confidential documents. Use synthetic examples when reporting bugs publicly.

Public demonstrations are illustrative. Do not describe them as production customer systems without verified approval and evidence.
